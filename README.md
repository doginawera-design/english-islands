# English Islands

Учебный сайт английского языка: словарь, произношение и интерактивные задания.

## Запуск

Статический сайт без установки зависимостей и сборки:

```bash
python3 -m http.server 8000 --directory dist
```

Откройте http://localhost:8000.

HTML, CSS, JavaScript, изображения и учебные материалы находятся в `dist/`. Для статического хостинга используйте эту папку.

## Синхронизация Sites → GitHub

Почасовая облачная задача отключена. После каждой завершённой правки сайта english-islands по запросу пользователя в этом чате ассистент переносит изменения из Sites в GitHub и проверяет результат до ответа о завершении. Отдельной команды на синхронизацию не требуется. Это шаг работы ассистента при правке, без фонового расписания или webhook. Передаются изменения в `dist/` и `.openai/hosting.json`. README и дополнительные файлы GitHub сохраняются. Обратная синхронизация и автоматическая публикация GitHub Pages не настроены.

Инструкция для каждого запуска:
1. Открыть Sites `appgprj_6a9c1e88a8248191b25545b52a845a83` через Sites tools. Получить новую краткосрочную source credential и восстановить checkout штатным Sites site-workflow. Не сохранять и не выводить токены; на этапе переноса не редактировать и не публиковать Sites повторно.
2. Назначение: `doginawera-design/english-islands`, ветка `main`. Через GitHub tools прочитать текущий head и полное рекурсивное дерево.
3. Найти последний коммит с сообщением `Sync Sites source: <SHA>`. До первого такого коммита использовать GitHub baseline `c6b417865aafdd8a55651f32b8005cfbd6a3ffc4`, соответствующий Sites source `5883ebd9ebb78088e5ac73f8bb197aa3bba5672b`.
4. Сравнить SHA blob и пути в исходнике Sites с последней синхронизированной копией GitHub для `dist/` и `.openai/hosting.json`. Если изменений источника нет, завершить без записи и уведомления.
5. Для каждого добавляемого, изменяемого или удаляемого в Sites пути сравнить текущую копию GitHub с baseline. Если GitHub содержит другое изменение этого же пути, сохранить обе стороны без перезаписи и сообщить о конфликте.
6. Через GitHub create_blob передать только новые/изменённые файлы; бинарные файлы кодировать base64. Проверить совпадение SHA с исходником. Уже существующие blob повторно не загружать. Через create_tree на текущем GitHub дереве включить изменения и удаления (sha:null). Сохранить все пути вне области синхронизации.
7. Создать один коммит `Sync Sites source: <точный SHA source HEAD>` с родителем — прочитанным текущим head GitHub. Перед update_ref ещё раз проверить head; если изменился, пересчитать изменения. Обновить main без force.
8. Прочитать main и рекурсивное дерево коммита; подтвердить соответствие изменённых файлов и удаления. Уведомлять кратко после переноса изменений или при ошибке; отсутствие изменений не требует сообщения. Незавершённую загрузку не считать успехом. Повторный запуск продолжает по SHA и не дублирует уже синхронизированное.
